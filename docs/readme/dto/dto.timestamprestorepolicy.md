## dto.TimestampRestorePolicy
TimestampRestorePolicy represents a policy for the point-in-time restore operation.

| Field                  | Description                                                                                                                                                                                                                                                       | Default Value |
|------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------|
| `bandwidth`            | Throttles read operations from the backup file(s) to not exceed the given I/O bandwidth in MiB/s.<br>Default: no limit.                                                                                                                                           |               |
| `batch-size`           | The max allowed number of records per an async batch write call.<br>Only applicable when using batch writes.                                                                                                                                                      | `128`         |
| `bin-list`             | The bins to restore (optional, an empty list implies restoring all bins).                                                                                                                                                                                         |               |
| `disable-batch-writes` | Disables the use of batch writes when restoring records to the Aerospike cluster.<br>By default, the cluster is checked for batch write support.                                                                                                                  | `false`       |
| `encryption`           | Encryption details (algorithm and key). Default is no encryption.<br>See: [dto.EncryptionPolicy](dto.encryptionpolicy.md)                                                                                                                                         |               |
| `extra-ttl`            | Amount of extra time-to-live to add to records that have expirable void-times.<br>Must be set in seconds.                                                                                                                                                         | `0`           |
| `max-async-batches`    | The max number of outstanding async record batch write calls at a time.                                                                                                                                                                                           | `128`         |
| `namespace`            | Namespace optionally specifies an alternative namespace name for the restore operation.<br>By default, the data is restored to the namespace from which it was taken.<br>See: [dto.RestoreNamespace](dto.restorenamespace.md)                                     |               |
| `no-generation`        | Records from backups take precedence. This option disables the generation check.<br>With this option, records from the backup always overwrite records that already exist in<br>the namespace, regardless of generation numbers.                                  | `false`       |
| `no-indexes`           | Do not restore any secondary index definitions.                                                                                                                                                                                                                   | `false`       |
| `no-records`           | Do not restore any record data (metadata or bin data).<br>By default, record data, secondary index definitions, and UDF modules will be restored.                                                                                                                 | `false`       |
| `no-udfs`              | Do not restore any UDF modules.                                                                                                                                                                                                                                   | `false`       |
| `parallel`             | The number of concurrent record readers from backup files.<br>This value controls the level of parallelism used by the backup service when<br>reading backup files.<br>The optimal value depends on hardware and network configuration.                           | `8`           |
| `replace`              | Replace records. This controls how records from the backup overwrite existing records in<br>the namespace. By default, restoring a record from a backup only replaces the bins<br>contained in the backup; all other bins of an existing record remain untouched. | `false`       |
| `retry-policy`         | Configuration of retries for each restore write operation.<br>If nil, the default policy is used (5 retries with a one-minute delay between attempts).<br>See: [dto.RetryPolicy](dto.retrypolicy.md)                                                              |               |
| `set-list`             | The sets to restore (optional, an empty list implies restoring all sets).                                                                                                                                                                                         |               |
| `socket-timeout`       | Timeout (ms) for Aerospike commands to write records, create indexes and create UDFs.<br>Socket timeout in milliseconds. Default is 10 minutes. If this value is 0, it is set to total-timeout.<br>If both are 0, there is no socket idle time limit.             | `60000`       |
| `total-timeout`        | Total socket timeout in milliseconds. Default is 0, that is, no timeout.                                                                                                                                                                                          | `0`           |
| `tps`                  | Throttles read operations from the backup file(s) to not exceed the given number of transactions per second.<br>Default: no limit.                                                                                                                                |               |
| `unique`               | Existing records take precedence. With this option, only records that do not exist in<br>the namespace are restored, regardless of generation numbers. If a record exists in<br>the namespace, the record from the backup is ignored.                             | `false`       |
